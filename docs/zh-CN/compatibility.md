# 一致性与对比

## 与标准库的一致性

PNG、JPEG、GIF、BMP、TIFF 的解码与编码以及默认缩放均改写自标准库与 `x/image` 的代码，仅将处理全图的部分改为按行处理，像素运算及其顺序保持不变。测试逐字节比对以下内容：

- 解码：Go 与 `x/image` 自带的 164 幅测试图像（PNG 85、JPEG 31、TIFF 17、WebP 17、BMP 9、GIF 5）解码所得像素与标准解码器相同（WebP 见下文）；对于截断文件和单字节损坏的文件，凡标准解码器报错者，本库同样报错。
- 缩放：默认算法与 `draw.CatmullRom.Scale` 逐字节一致。灰度图像仅计算单一通道并输出为灰度图像，其数值即 `x/image` 输出的红、绿、蓝三个相等通道的值。
- 编码：JPEG（不设选项时）与 GIF（启用 `FixedPalette` 时；同时启用 `NoDither` 时与使用 `draw.Src` 的 `gif.Encode` 一致）与标准库逐字节一致；BMP、TIFF 与 `x/image` 逐字节一致（不含元数据时）。PNG（不减色时）在使用 6 级（指定，或 Go 1.26 下的默认值）且图像数据不超过一个压缩块（256KB）时与 `png.Encode` 逐字节一致；Go 1.27 下默认使用 7 级（见[压缩](compression.md)），更大的图像分块压缩，像素相同。
- 模糊与反锐化掩模：对于不含透明通道的图像，`Blur` 与 Pillow 12.1.1 的 `GaussianBlur`、`Sharpen(SharpenOptions{...})` 与其 `UnsharpMask` 逐字节一致（测试中存有 Pillow 生成的参考图像，sigma 0.7–40）。算法与定点运算移植自 Pillow 的 C 代码。
- 灰度：与 Pillow 的 `convert("L")` 逐字节一致，即 `color.RGBToYCbCr` 的亮度；在全部 1677 万种颜色上，与精确的 Rec. 601 亮度最多相差 0.5 级。（`color.GrayModel` 先计算至 16 位再舍去低 8 位，最多相差 0.99 级，且 16% 的颜色未取到最近的一级，故未采用。）
- 色彩调整：与 sharp 0.35（libvips 8.18）的 `modulate` 相比，每个像素相差不超过 1，平均 0.14。
- 转换至 sRGB：在 Display P3（采样曲线与参数曲线两种表示）和 Adobe RGB（gamma 曲线）三种配置下，与 LittleCMS 的每个值相差不超过 1，约 1.6% 的值相差 1。
- 任意角度旋转：距边缘 2 像素以上的区域，每个像素与 Pillow 的双线性旋转（`expand=True`）相差不超过 1。边缘有意不同：本库将最外一圈像素按覆盖比例与背景混合（与 libvips 相同），边缘平滑；Pillow 为硬边。画布取恰好容纳全图的最小尺寸，三者的计算方式各不相同：将 150×103 旋转 30° 时，本库与 Pillow 得到 182×165，sharp 四舍五入为 181×164（角部会被裁去少许）。
- 所有新操作及各编码器的输出在 x86-64 与 32 位 x86 上逐字节一致；ARM64、PowerPC、s390x、RISC-V、LoongArch、MIPS 由自动测试中的校验值测试核对（浮点运算中每个乘积先取整再相加，以免部分处理器将乘加融合为一条指令而导致结果不同）。

## 有意的差异

- **GIF 调色板**：标准库将所有非调色板图像一律降为固定的 256 色（Plan 9 调色板），照片仅 25dB。本库默认依据图像内容选色，同一照片可达 39dB；界面截图由 29dB 提高到 58dB，且文件更小。`FixedPalette` 可切换回标准库的方式。动画同样依据全部帧统一选色。
- **有损 WebP 的颜色**：`x/image` 按 JPEG 的取值范围换算 WebP 的亮度与色度，颜色对比度低于 libwebp（浏览器）的结果，实测平均相差 6–8 个色阶，最大 33。本库对取值范围做了校正，在真实照片上与 libwebp 平均相差 0.4–0.6 个色阶；色彩边缘处仍有差异（色度插值方式不同，最大 20–40）。
- **ICC**：输入带有 ICC 色彩配置时默认写入输出，因此此类图像的输出比标准库编码多出 ICC 数据；调用 `StripICC()` 后两者相同。
- 以 JPEG、YCbCr、CMYK 等为来源输出 PNG 时写为 8 位 RGB；`png.Encode` 写为 16 位。
- 基线 JPEG 文件若在一次完整扫描之后再出现扫描（极少见），则予以拒绝。
- 尺寸为 0 的 GIF / BMP / WebP 予以拒绝；标准库返回空图像。
- `x/image` 拒绝读取的 WebP 动画，本库读出其第一帧在画布上的样子：帧位于其位置，画布其余部分透明；帧内像素与该帧码流作为静态图像解码的结果相同。
- JPEG 质量超出 1–100 时返回错误；标准库则静默截断至有效范围。
- 渐进式 JPEG 的系数以 16 位存储，超出范围（仅见于损坏文件）时返回错误。
- **含透明通道图像的模糊与锐化**：按预乘透明度计算，透明像素的颜色不会渗入相邻像素；Pillow 对 RGBA 四个通道分别模糊，透明区域的颜色（通常为黑色）会使边缘变暗。

## WebP 编码器

WebP 编码器由本模块自行实现，无标准库可供对照，因此采用两种解码器验证：`x/image` 与 libwebp（通过 Python PIL）的解码结果一致，无损编码可逐像素还原。与 libwebp 的对比如下（测试环境同[实测](performance.md#实测)）：

- 有损：7 张真实照片分别以质量 30–95 编码，与 libwebp 1.6（Pillow 12.1.1，默认 method 4）比较同等画质下的文件大小（均以 libwebp 解码后计算）：同等 SSIM 时小 2.4%，同等 PSNR 时小 4.8%；与 libwebp 最慢的 method 6 相比亦小 1.6% / 1.5%。
  - 分段量化移植自 libwebp（按宏块系数的分布将宏块分为 4 段，平坦区域量化较细、纹理区域较粗，强度采用 libwebp 的默认值）：不分段时，同等 PSNR 下文件小 8.9%，但同等 SSIM 下仅与 libwebp 持平，纹理较多的两张照片大 13%；分段后这两张仅大 1%。在相同质量设置下，文件比 libwebp 同质量设置的结果小 5–25%。
  - 曾参照 libwebp 试验网格量化，多种强度均无净收益（同等 SSIM 与同等 PSNR 下的结果一升一降），因此未予采用：本编码器的量化已偏向零取整，网格量化可节省的空间有限。
- 无损：默认级别下，文件大小相对 libwebp 在 −8.5% 至 +6% 之间，照片多数更小。

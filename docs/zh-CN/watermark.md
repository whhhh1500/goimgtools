# 隐形水印

`InvisibleWatermark` 把几个字节（1 至 32 个：用户 ID、订单号等）藏进图像；`inspect.ReadWatermark` 用同一密钥从副本中读回，不需要原图。分两种：

- **`WatermarkBlind`（默认，盲水印）**：标明图像来源，经得起对文件的各种处理：重新存为 JPEG 或 WebP、缩放、裁剪、旋转、调亮度与对比度、截图。默认强度下很难看出（见下文实测）。
- **`WatermarkScreen`（防泄露水印）**：在此之外还经得起对着屏幕拍照（透视、镜头模糊、摩尔纹、相机自身的处理），因此给某人看过的图像被拍照或截图后，能追查到此人。它更强、细节更大，平坦区域近看能见到一层淡淡的纹理。

两种都可设强度 `Strength` 与密度 `Density`。

```go
// 加水印：密钥是读取（以及伪造）水印所需的秘密。
err := goimgtools.Open("in.jpg").
    InvisibleWatermark([]byte("user-1234"), goimgtools.InvisibleWatermarkOptions{
        Kind: goimgtools.WatermarkScreen, Key: "our secret",
    }).
    JPEG(goimgtools.JPEGOptions{Quality: 90}).
    ToFile("shown.jpg")

// 读水印：从副本、截图、裁到屏幕范围的照片中读取。
mark, found, err := inspect.ReadWatermark(goimgtools.Open("leaked.jpg"), "our secret")
```

读取一张 3000×2000 的图，有水印时约 0.8 秒，没有时约 1.6 秒（要多试几种方法），内存约 80MB。设置 `Threads`（或 `SetDefaultThreads`）后搜索会分摊到多个核上，结果相同：8 核时为 0.6 秒与 0.8 秒。

```bash
goimgtools -mark user-1234 -mark-key "our secret" -mark-kind screen in.jpg shown.jpg
goimgtools readmark -key "our secret" leaked.jpg
```

## 设置

| 字段 | 含义 |
|---|---|
| `Kind` | `WatermarkBlind` 或 `WatermarkScreen`（见上） |
| `Key` | 生成水印用的密钥：只有同一密钥能找到并读出水印，没有它也无法伪造。空字符串也是一个密钥 |
| `Strength` | 水印幅度的倍数：1（默认）为该种类的平衡点；0.5 更难看出也更难读出；2 更经得起破坏，也更容易看出；最大 16 |
| `Density` | 水印沿短边大约重复几次，1 至 16（默认 4）。越密，越小的一块图像仍带有完整的水印（裁剪须在每个方向保留约两次重复）；但细节也越细，缩小得更多的图像更难读出（每个细节至少 2 像素，`WatermarkScreen` 至少 3 像素） |

字节越少，越能从损坏严重的副本中读回：字节经卷积码（约束长度 9、码率 1/6）保护并分散到数千个位置，字节少则每一位分到的位置多。读出的结果几乎不可能是错误的水印：一次搜索要试两千种左右的读法，每种都校验密钥与字节的 32 位 CRC，没有水印或密钥不对的图像读出假水印的机会约为两百万分之一；读不到时 `found == false`。

## 原理

- **图块**：水印是一块 64×64 码片的图块，铺满图像的亮度通道，每个码片宽几个像素。每个码片的值由三种信号混合而成，都由密钥生成：16 个已知频率的正弦参考信号（占功率的 25%）、随机正负号的同步图案（20%），以及载荷（55%）。参考信号是水印中最容易被看出的部分，频率越低越明显：因此只给它四分之一的功率，频率取每个图块 10 至 20 周，同样可见度下整体可以更强。载荷的各位经编码后分散到各码片上。
- **加在哪里**：加在图像最能藏住它的地方，纹理多处多加，平坦处少加（Voloshynovskiy 等人的噪声可见度函数）；并从纯白、纯黑处往回推，否则会被截断。
- **逐行加入**：各行一到即加，只用每行周围几行。在任何处理器、任何线程数下结果都相同。
- **找出图块的排布**：读取时先把副本的频谱拉平，再按各处的干净程度加权，使平坦区域（拉平后基本只剩水印）与纹理区域同样起作用。然后在整幅图像及其中部，按各种尺寸、角度（含镜像）搜索参考信号的峰。这是 Pereira 与 Pun、以及 Digimarc 的模板法；照片中部受透视的影响较小。
- **对准**：把图块的所有副本叠到一起，水印相加而图像本身被平均掉；同步图案（加上部分参考信号）确定图块从哪里开始。随后用图像的两半校正对准，再逐区域拟合单应变换；区域太弱时，改由四个窗口中图块的大小推算（单应变换下图块所占面积随其分母的三次方变化）。最后译出载荷：为此把图块再叠一次，各处加权：按拉平后的图像在其周围的纹理多少把各处分成十二类，每类按它所含水印与噪声之比计入，两者都用每个图块都有的部分（同步图案与参考信号）测出。平坦处压缩后水印所剩无几，纹理多处水印被图像淹没，介于两者之间的地方含水印最多。同样的已知部分还显示了副本在各频率上把水印削弱了多少（重采样、压缩造成的模糊）；先把这部分扣除，余下的再按同样的响应、除以该频率剩余的噪声加权（匹配滤波）。随后对每种载荷长度校验最可能的几个比特序列的 CRC，最吻合的几种长度多校验一些（先用 Viterbi 算法，再沿其网格从后往前做最优优先搜索，按可能性从高到低依次给出序列）。

## 实测

测试图像为三张照片（1500×844、1280×720、1600×500）、一张小照片（640×360），以及一张以白色为主的界面截图（1280×900），各藏入 9 个字节。每张加了水印的图像都用 Pillow 做同一组攻击；同类开源库中用得最多的 [blind_watermark](https://github.com/guofei9987/blind_watermark) 以其默认设置按同样方式测量。表中数字为 5 张中正确读回水印的张数。

| 攻击 | 盲水印（默认） | 盲水印，`Strength: 1.5` | 防泄露（默认） | blind_watermark |
|---|---|---|---|---|
| 无 | 5 | 5 | 5 | 5 |
| JPEG 质量 90 / 70 / 50 / 30 | 5 / 5 / 4 / 4 | 5 / 5 / 4 / 4 | 5 / 5 / 5 / 4 | 5 / 4 / 4 / 3 |
| WebP 质量 60 | 3 | 3 | 4 | 3 |
| 缩小一半 | 5 | 5 | 5 | 0 |
| 缩到 70%，再存 JPEG 80 | 5 | 5 | 5 | 0 |
| 裁到每边 40% / 25% | 4 / 1 | 4 / 2 | 3 / 2 | 0 / 0 |
| 旋转 3° / 30° 后裁剪 | 5 / 4 | 5 / 5 | 5 / 5 | 0 / 0 |
| 调暗（×0.8）/ 加对比度（×1.3） | 5 / 4 | 5 / 4 | 5 / 5 | 4 / 4 |
| 噪声（σ 8） | 4 | 5 | 5 | 5 |
| 截图（以 1366 宽显示，JPEG 90） | 5 | 5 | 5 | 3 |
| 透视（四角最多移动 4%），JPEG 85 | 5 | 5 | 5 | 0 |
| 对着屏幕拍照（模拟：透视、镜头模糊、缩到 3/4、伽马、摩尔纹、传感器噪声、锐化、JPEG 85） | 2 | 4 | 5 | 0 |

对图像的改变（五张的平均；SSIMULACRA2：90 以上看不出差别，70 为高质量；butteraugli：小于 1 为不可见）：

| | PSNR | SSIMULACRA2 | butteraugli |
|---|---|---|---|
| 盲水印（默认） | 45.3 dB | 79.7 | 3.9 |
| 盲水印，`Strength: 1.5` | 41.8 dB | 68.1 | 5.8 |
| 防泄露（默认） | 38.9 dB | 51.0 | 9.4 |
| blind_watermark（默认） | 37.7 dB | 40.4 | 5.5 |

blind_watermark 无法从尺寸或角度变过的图像中读出水印：它的 `recover` 要靠原图先把图像还原，所以这里所有几何攻击都失败。取 `Strength: 1.5` 时，按 PSNR 与 SSIMULACRA2 本库对图像的改变比 blind_watermark 小，按 butteraugli 则大一些；此时本库的盲水印对 JPEG 的承受力比它强，对 WebP 与强噪声与它相当，所有几何攻击也都经得起。

其余攻击（缩小一半、缩到 70% 再存 JPEG 80、调暗、加对比度、噪声、截图）本库水印与 TrustMark 都读出 23 或 24 张（`P` 加对比度后为 22 张）；blind_watermark 与 invisible-watermark 缩小一半后一张也读不出。在这些照片上，本库盲水印取默认设置时对图像的改变远小于 TrustMark `Q`（SSIMULACRA2 76.9 对 54.7，butteraugli 2.7 对 9.5），JPEG 与 WebP 之后读出的张数却与它相同；按 butteraugli 可见度与本库相当的 TrustMark `P`，JPEG 50 时只读出 1 张。纹理丰富的照片容易藏住水印；第一组图中以白色为主的截图和那张又宽又矮的照片更难。

另做了一组更严苛的拍屏模拟，用本库自己的操作完成，透视更强，锐化用 Pillow 的锐化。在这组模拟下，防泄露水印能从三张照片全部读出，小照片和界面截图读不出；只去掉其中任意一步时，5 张中能读出 3 到 5 张。

## 局限

- **可见度与鲁棒性此消彼长**：能扛住相机的水印，近看平坦处会有淡淡的纹理；完全看不出的水印承受力就低。`Strength` 在两者之间调节：盲水印取 1，适合一直以数字形式流转的图像：这里照片再保存为 JPEG 时直到质量 30 都能读出，保存为 WebP 60 时 5 张中读出 3 张（WebP 的滤波去掉得更多）；压缩更狠或图像平坦时取 1.5 至 2；可能被拍照的图像用防泄露水印。
- **平坦的图像承载得少**：以白色为主的界面或文档，可藏水印的地方少，平坦处只能弱弱地带上水印。这类图像请调高 `Strength`。
- **小图与小块裁剪包含的重复次数少**：640×360 及以下的图像受损严重后更难读出。裁剪须在每个方向保留约两次重复；可能被裁剪时调高 `Density`，代价是水印细节更细。
- **对着屏幕拍的照片**：请先把照片裁到屏幕范围，拍摄角度不要太斜。上述结果来自模拟，实际的手机、屏幕与距离各不相同。
- **它不是锁**：知道有水印的人仍可把它破坏到读不出（强噪声、强模糊、重绘图像）。密钥能防止他人读出或伪造水印，但不能防止水印被破坏。

# 隐形水印

`InvisibleWatermark` 把几个字节（1 至 32 个：用户 ID、订单号等）藏进图像；`inspect.ReadWatermark` 用同一密钥从副本中读回，不需要原图。分两种：

- **`WatermarkBlind`（默认，盲水印）**：标明图像来源，经得起对文件的各种处理：重新存为 JPEG 或 WebP、缩放、裁剪、旋转、调亮度与对比度、截图。默认强度下很难看出（见下文实测）。
- **`WatermarkScreen`（防泄露水印）**：在此之外还经得起对着屏幕拍照（透视、镜头模糊、摩尔纹、相机自身的处理），因此给某人看过的图像被拍照或截图后，能追查到此人。它更强、细节更大，平坦区域近看能见到一层淡淡的纹理。

两种都可设强度 `Strength` 与密度 `Density`。

```go
// 加水印：密钥是读取（以及伪造）水印所需的秘密。
err := goimgtools.Open("in.jpg").
    InvisibleWatermark([]byte("user-1234"), goimgtools.InvisibleWatermarkOptions{
        Kind: goimgtools.WatermarkScreen, Key: "our secret",
    }).
    JPEG(goimgtools.JPEGOptions{Quality: 90}).
    ToFile("shown.jpg")

// 读水印：从副本、截图、裁到屏幕范围的照片中读取。
mark, found, err := inspect.ReadWatermark(goimgtools.Open("leaked.jpg"), "our secret")
```

```bash
goimgtools -mark user-1234 -mark-key "our secret" -mark-kind screen in.jpg shown.jpg
goimgtools readmark -key "our secret" leaked.jpg
```

## 设置

| 字段 | 含义 |
|---|---|
| `Kind` | `WatermarkBlind` 或 `WatermarkScreen`（见上） |
| `Key` | 生成水印用的密钥：只有同一密钥能找到并读出水印，没有它也无法伪造。空字符串也是一个密钥 |
| `Strength` | 水印幅度的倍数：1（默认）为该种类的平衡点；0.5 更难看出也更难读出；2 更经得起破坏，也更容易看出；最大 16 |
| `Density` | 水印沿短边大约重复几次，1 至 16（默认 4）。越密，越小的一块图像仍带有完整的水印（裁剪须在每个方向保留约两次重复）；但细节也越细，缩小得更多的图像更难读出（每个细节至少 2 像素，`WatermarkScreen` 至少 3 像素） |

字节越少，越能从损坏严重的副本中读回：字节经卷积码保护并分散到数千个位置，字节少则每一位分到的位置多。读出的结果几乎不可能是错误的水印：一次搜索要试一千种左右的读法，每种都校验密钥与字节的 32 位 CRC，没有水印或密钥不对的图像读出假水印的机会约为百万分之一；读不到时 `found == false`。

## 原理

- **图块**：水印是一块 64×64 码片的图块，铺满图像的亮度通道，每个码片宽几个像素。每个码片的值由三种信号混合而成，都由密钥生成：24 个已知频率的正弦参考信号、随机正负号的同步图案，以及载荷。载荷的各位经编码后分散到各码片上。
- **加在哪里**：加在图像最能藏住它的地方，纹理多处多加，平坦处少加（Voloshynovskiy 等人的噪声可见度函数）；并从纯白、纯黑处往回推，否则会被截断。
- **逐行加入**：各行一到即加，只用每行周围几行。在任何处理器、任何线程数下结果都相同。
- **找出图块的排布**：读取时先把副本的频谱拉平，再按各处的干净程度加权，使平坦区域（拉平后基本只剩水印）与纹理区域同样起作用。然后在整幅图像及其中部，按各种尺寸、角度（含镜像）搜索参考信号的峰。这是 Pereira 与 Pun、以及 Digimarc 的模板法；照片中部受透视的影响较小。
- **对准**：把图块的所有副本叠到一起，水印相加而图像本身被平均掉；同步图案（加上部分参考信号）确定图块从哪里开始。随后用图像的两半校正对准，再逐区域拟合单应变换；区域太弱时，改由四个窗口中图块的大小推算（单应变换下图块所占面积随其分母的三次方变化）。最后译出载荷：每个图块都有的同步图案与参考信号，显示了副本在各频率上把水印削弱了多少（重采样、压缩造成的模糊）；先把这部分扣除，余下的再按同样的响应、除以该频率剩余的噪声加权（匹配滤波），然后用列表 Viterbi 依次校验四个最可能的比特序列。

## 实测

测试图像为三张照片（1500×844、1280×720、1600×500）、一张小照片（640×360），以及一张以白色为主的界面截图（1280×900），各藏入 9 个字节。每张加了水印的图像都用 Pillow 做同一组攻击；同类开源库中用得最多的 [blind_watermark](https://github.com/guofei9987/blind_watermark) 以其默认设置按同样方式测量。表中数字为 5 张中正确读回水印的张数。

| 攻击 | 盲水印（默认） | 盲水印，`Strength: 1.5` | 防泄露（默认） | blind_watermark |
|---|---|---|---|---|
| 无 | 5 | 5 | 5 | 5 |
| JPEG 质量 90 / 70 / 50 / 30 | 5 / 4 / 4 / 2 | 5 / 4 / 4 / 3 | 5 / 5 / 5 / 4 | 5 / 4 / 4 / 3 |
| WebP 质量 60 | 1 | 2 | 4 | 3 |
| 缩小一半 | 4 | 5 | 5 | 0 |
| 缩到 70%，再存 JPEG 80 | 3 | 4 | 5 | 0 |
| 裁到每边 40% / 25% | 2 / 1 | 4 / 2 | 3 / 1 | 0 / 0 |
| 旋转 3° / 30° 后裁剪 | 4 / 4 | 5 / 4 | 5 / 4 | 0 / 0 |
| 调暗（×0.8）/ 加对比度（×1.3） | 5 / 4 | 5 / 4 | 5 / 4 | 4 / 4 |
| 噪声（σ 8） | 4 | 4 | 5 | 5 |
| 截图（以 1366 宽显示，JPEG 90） | 5 | 5 | 5 | 3 |
| 透视（四角最多移动 4%），JPEG 85 | 5 | 5 | 5 | 0 |
| 对着屏幕拍照（模拟：透视、镜头模糊、缩到 3/4、伽马、摩尔纹、传感器噪声、锐化、JPEG 85） | 3 | 5 | 5 | 0 |

对图像的改变（五张的平均；SSIMULACRA2：90 以上看不出差别，70 为高质量；butteraugli：小于 1 为不可见）：

| | PSNR | SSIMULACRA2 | butteraugli |
|---|---|---|---|
| 盲水印（默认） | 45.8 dB | 79.5 | 4.6 |
| 盲水印，`Strength: 1.5` | 42.3 dB | 68.0 | 7.0 |
| 防泄露（默认） | 39.4 dB | 50.9 | 10.2 |
| blind_watermark（默认） | 37.7 dB | 40.4 | 5.5 |

blind_watermark 无法从尺寸或角度变过的图像中读出水印：它的 `recover` 要靠原图先把图像还原，所以这里所有几何攻击都失败。取 `Strength: 1.5` 时，按 PSNR 与 SSIMULACRA2 本库对图像的改变比 blind_watermark 小，按 butteraugli 则大一些；此时本库的盲水印对 JPEG 的承受力与它相当（WebP 与强噪声略逊），所有几何攻击也都经得起。

| | PSNR | SSIMULACRA2 | butteraugli | JPEG | WebP 60 | 裁到 40% | 旋转 3° | 透视 | 对着屏幕拍照 |

| [blind_watermark](https://github.com/guofei9987/blind_watermark) | 37.7 dB | 40.4 | 5.5 | 5 / 4 / 4 / 3 | 3 | 0 | 0 | 0 | 0 |
| [invisible-watermark](https://github.com/ShieldMnt/invisible-watermark) `dwtDctSvd`（Stable Diffusion 所用） | 40.5 dB | 75.1 | 3.4 | 4 / 0 / 0 / 0 | 0 | 0 | 0 | 0 | 0 |
| [TrustMark](https://github.com/adobe/trustmark) `Q`（Adobe 的默认模型） | 45.1 dB | 68.8 | 8.3 | 5 / 5 / 5 / 4 | 5 | 0 | 0 | 4 | 4 |
| TrustMark `P` | 50.0 dB | 86.3 | 3.7 | 5 / 4 / 3 / 0 | 4 | 0 | 0 | 0 | 0 |

invisible-watermark 在未受任何处理的 5 张图上只能读回 4 张（`dwtDct` 只有 3 张，可见度更低：SSIMULACRA2 87.1）。TrustMark 是需要 PyTorch 的一对神经网络，对重新压缩的承受力最强：在与本库盲水印 `Strength: 1.5` 相当的可见度下（其 `Q` 模型），JPEG 30 读出 4 张、WebP 60 读出 5 张，本库为 3 张与 2 张；但凡经过裁剪或旋转就一张也读不出，因为它的解码器直接读取整幅图像。这几种方案中，只有本库的水印经得起裁剪与旋转。

另做了一组更严苛的拍屏模拟，用本库自己的操作完成，透视更强，锐化用 Pillow 的锐化。在这组模拟下，防泄露水印能从三张照片中的两张读出（第三张处在临界：用 Go 自带的 JPEG 解码器解出的副本能读出），小照片和界面截图读不出；只去掉其中任意一步时，5 张中能读出 3 到 4 张。

## 局限

- **可见度与鲁棒性此消彼长**：能扛住相机的水印，近看平坦处会有淡淡的纹理；完全看不出的水印承受力就低。`Strength` 在两者之间调节：盲水印取 1，适合一直以数字形式流转、再保存为 JPEG 时质量在 70 以上（或 WebP 约 90，WebP 的滤波去掉得更多）的图像；压缩更狠时取 1.5 至 2；可能被拍照的图像用防泄露水印。
- **平坦的图像承载得少**：以白色为主的界面或文档，可藏水印的地方少，平坦处只能弱弱地带上水印。这类图像请调高 `Strength`。
- **小图与小块裁剪包含的重复次数少**：640×360 及以下的图像受损严重后更难读出。裁剪须在每个方向保留约两次重复；可能被裁剪时调高 `Density`，代价是水印细节更细。
- **对着屏幕拍的照片**：请先把照片裁到屏幕范围，拍摄角度不要太斜。上述结果来自模拟，实际的手机、屏幕与距离各不相同。
- **它不是锁**：知道有水印的人仍可把它破坏到读不出（强噪声、强模糊、重绘图像）。密钥能防止他人读出或伪造水印，但不能防止水印被破坏。

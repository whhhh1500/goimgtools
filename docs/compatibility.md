# Compatibility and comparisons

## Compatibility with the standard library

Decoding and encoding of PNG, JPEG, GIF, BMP and TIFF, and the default resizing, are all adapted from the code of the standard library and `x/image`. Only the parts that work on the whole image were changed to work row by row; the pixel arithmetic and its order are unchanged. The tests compare byte for byte:

- Decoding: the 164 test images that come with Go and `x/image` (PNG 85, JPEG 31, TIFF 17, WebP 17, BMP 9, GIF 5) decode to the same pixels as with the standard decoders (for WebP see below); for truncated files and files with a single corrupted byte, where the standard decoder reports an error, so does this one.
- Resizing: the default algorithm is byte-for-byte identical to `draw.CatmullRom.Scale`. A grayscale image is computed on one channel only and output as a grayscale image; the values are those of the three equal red, green and blue channels that `x/image` gives.
- Encoding: JPEG (with no options) and GIF (with `FixedPalette`; with `NoDither` added as well, identical to `gif.Encode` using `draw.Src`) are byte-for-byte identical to the standard library; BMP and TIFF are byte-for-byte identical to `x/image` (without metadata). PNG (without colour reduction) is byte-for-byte identical to `png.Encode` when level 6 is set and the image data is no larger than one compression block (256KB); the default is level 7 (see [Compression](compression.md)), and larger images are compressed in blocks, with the same pixels.
- Blur and unsharp mask: for images without an alpha channel, `Blur` is byte-for-byte identical to Pillow 12.1.1's `GaussianBlur`, and `Sharpen(SharpenOptions{...})` to its `UnsharpMask` (the tests store reference images generated by Pillow, sigma 0.7–40). The algorithms and the fixed-point arithmetic were ported from Pillow's C code.
- Greyscale: byte-for-byte identical to Pillow's `convert("L")`, that is, the luma of `color.RGBToYCbCr`; over all 16.77 million colours it differs from the exact Rec. 601 luma by at most 0.5 levels. (`color.GrayModel` first computes to 16 bits and then drops the low 8 bits; it differs by up to 0.99 levels, and for 16% of colours it is not the nearest level, so it was not followed.)
- Colour adjustment: differs from `modulate` in sharp 0.35 (libvips 8.18) by no more than 1 per pixel, 0.14 on average.
- Conversion to sRGB: with three profiles, Display P3 (written both as a sampled curve and as a parametric curve) and Adobe RGB (gamma curve), every value differs from LittleCMS by no more than 1, and about 1.6% of values differ by 1.
- Rotation by any angle: at 2 pixels or more from the edges, every pixel differs from Pillow's bilinear rotation (`expand=True`) by no more than 1. The edges differ on purpose: this library blends the outermost ring of pixels with the background by coverage (as libvips does), so the edge is smooth; Pillow gives a hard edge. The canvas is the smallest size that just holds the whole image, and each of the three works it out differently: rotating 150×103 by 30° gives 182×165 for this library and Pillow, while sharp rounds to 181×164 (cutting off a little of the corners).
- The output of all new operations and of each encoder is byte-for-byte identical on x86-64 and 32-bit x86; ARM64, PowerPC, s390x, RISC-V, LoongArch and MIPS are checked by the checksum tests in CI (in floating-point arithmetic each product is rounded before it is added, so that processors which fuse a multiply and an add into one instruction do not give different results).

## Deliberate differences

- **GIF palette**: the standard library reduces every non-paletted image to a fixed 256 colours (the Plan 9 palette), which gives only 25dB on photos. By default this library chooses colours from the image content: 39dB on the same photo; a UI screenshot goes from 29dB to 58dB, and the file is smaller too. `FixedPalette` switches back to the standard library's way. Animations likewise choose colours from all frames together.
- **Lossy WebP colours**: `x/image` converts WebP luma and chroma as if they used JPEG's value ranges, so colours have lower contrast than with libwebp (browsers); measured, the average difference is 6–8 levels, the maximum 33. This library corrects the range: on real photos it differs from libwebp by 0.4–0.6 levels on average; there are still differences at colour edges (the chroma is interpolated differently; maximum 20–40).
- **ICC**: when the input has an ICC profile, it is written into the output by default, so for such images the output has extra ICC data compared with standard library encoding; after `StripICC()` they are the same.
- For JPEG, YCbCr, CMYK and similar sources, PNG output is written as 8-bit RGB; `png.Encode` writes 16-bit.
- Baseline JPEG files in which another scan appears after one complete scan (very rare) are rejected.
- GIF / BMP / WebP with a size of 0 are rejected; the standard library returns an empty image.
- A JPEG quality outside 1–100 gives an error; the standard library silently clamps it into range.
- Progressive JPEG coefficients are stored as 16 bits; a value out of range (which appears only in corrupt files) gives an error.
- **Blur and sharpening of images with an alpha channel**: computed with premultiplied alpha, so the colour of transparent pixels does not bleed into their neighbours; Pillow blurs each of the four RGBA channels separately, and the colour in transparent areas (often black) darkens the edges.

## WebP encoders

The WebP encoders were written for this module. There is no standard library to compare against, so they are verified with two decoders: `x/image` and libwebp (through Python PIL) decode to the same result, and lossless encoding is restored pixel for pixel. Comparison with libwebp (test environment as in [Benchmarks](performance.md#benchmarks)):

- Lossy: 7 real photos, each encoded at qualities 30–95, compared with libwebp 1.6 (Pillow 12.1.1, default method 4) on file size at equal image quality (both decoded with libwebp before measuring): 2.4% smaller at equal SSIM, 4.8% smaller at equal PSNR; also 1.6% / 1.5% smaller than libwebp's slowest setting, method 6.
  - Segment-based quantization ported from libwebp (macroblocks split into 4 segments by the distribution of their coefficients, finer quantization in flat areas and coarser in textured ones, at libwebp's default strength): without segments, files are 8.9% smaller at equal PSNR, but only level with libwebp at equal SSIM, and 13% larger on the two photos with the most texture; with segments, these two are only 1% larger. At the same quality setting, files are 5–25% smaller than libwebp's at that quality.
  - Trellis quantization was tried as in libwebp; none of several strengths gave a net gain (at equal SSIM and at equal PSNR, one went up and the other down), so it was not added: this encoder's quantization already rounds towards zero, so there is little left for trellis quantization to save.
- Lossless: at the default level, file size is between −8.5% and +6% of libwebp's; photos are mostly smaller.
